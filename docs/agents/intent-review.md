# Per-PR Intent review

`check-skills` (`validate / Validate intent skills`) fails a PR with any pending Intent review item, so every PR whose changes Intent tracks, each stacked PR included, records its own review. CI checks against the PR base, so `<base>` is `$(git merge-base origin/main HEAD)` for a PR against main and `$(git merge-base <parent branch> HEAD)` for a stacked PR.

Before step 1, make sure no file or symlink is on disk, untracked or gitignored, at a path this PR deleted. Intent hashes the working tree, so it records the content of that file, which CI does not have, and `check-skills` fails on CI even when the local check passes. Remove or move such a file first. `scripts/intent-restack.sh record` refuses this state with exit 1 for the same reason.

1. Run `pnpm exec intent maintainer review --base <base> --json > .intent/review.json`. `.intent/**` is outside Intent's review.
2. In that report, set `outcome`, `reason` and `evidence` on this PR's items: the items whose files this PR changed, and the skill and planning items whose coverage this PR changed through a `sources:` edit in a SKILL.md. Such an item also lists the file it newly covers or uncovers, even when this PR left that file unchanged: in its `changedFiles`, or, for an item with no record yet, only in its `snapshot`. It still gets an outcome here. Leave every other item unannotated: the list can include skill and planning items outside the diff.
3. Run `pnpm exec intent maintainer review --record .intent/review.json` (it takes no `--base`), then delete `.intent/review.json`. When step 2 annotated no item, skip `--record` (Intent refuses a report that annotates none of its items), delete `.intent/review.json` and handle the remaining items as the closing paragraph says. After any further edit, start again at step 1: recording rejects an item whose files changed since the report.
4. Commit `.intent/review-state.json` in the PR's last commit, and confirm `pnpm exec intent maintainer check --base <base>` passes.

An item left unannotated still fails that check. When an untracked file the workflow made caused it, delete that file (only files the workflow made, never the user's) and start again at step 1. When the item belongs to a lower stack layer, record it in that layer. A `sources:` edit in a SKILL.md can add the files it newly covers or uncovers to the skill and planning items; `scripts/intent-restack.sh record` leaves an item pending when such a file is outside the layer's diff: record it through steps 1-4, annotating it as step 2 says.
