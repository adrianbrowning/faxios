Breaking: A string body with a JSON `Content-Type` is sent as written (trimmed) and is no longer run through `JSON.parse`, so a string that isn't valid JSON is sent as is instead of being wrapped in quotes as a JSON string. A custom `env.fetch` now gets one `Request` that carries the body, plus an init that repeats the Request's members with an own `body` that adds no new body (`null` in Node and Deno, `undefined` in Bun); read the body from the `Request` (`await input.text()`), not `init.body` (with `env.Request: null` the body is still in `init.body`). `init.headers` is now the Request's `Headers` object instead of a plain object, so `init.headers["content-type"]` is `undefined`; use `init.headers.get("content-type")`. `init.duplex` is set only for a stream body. Each request now does its work once: the body is read once, header values are sanitized once, a rejected request's stack is stitched only when `error.stack` is read, and `mergeConfig` no longer rebuilds its merge strategies on every call. The `forwardTo` plugin forwards the body from the adapter's `Request`: a stream body as a stream, any other body as bytes with its Content-Length.
